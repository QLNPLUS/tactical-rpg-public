# 长期路线图：多人战斗与阵营 / PvP

本文件只描述已批准的阶段划分与预留边界，不承诺任何日期。已完成的里程碑仍以 [README 的路线图](../README.md#路线图) 与验证记录为准；本文件描述的是**尚未完成**的部分。

## CURRENT｜本轮：多人合作 PvE（检查点为单场；工作区候选已加多场并行，未验收）

范围与验收口径见本轮批准计划的第 3 节（单场多人合作 PvE）与第 4 节（实施包与交接门槛）；该计划属内部过程材料，不随源码分发。要点：

- 检查点 `d988716`：全服同时只有一场战斗，一场内可有多个真实玩家参战。工作区候选：多场并行——不同维度各自开战，同维度内战区包围盒重叠按保守 AABB 拒绝新场。两种状态下都是共享 ATB 与公共战况，各自独立 AP、MP、冷却、连续行动费用、移动与防御状态。
- 加入有两条：显式邀请并接受，或附近战场直接确认加入；两者都由服务端按连接身份重算同维度、距离、战区、存活、未参战与容量（默认上限 4 人，`maxBattlePlayers` 1..16，每场构造时快照，可配置不等于已验证承载量）。中途加入从零充能，安全动作边界加入。
- 只有本人可在自己的回合发起战斗动作；等待者观战。不能借容器、技能范围请求或旧数据包绕过权限。
- 死亡、断线、换维度、成功逃跑只移除本人；当前行动者离开则推进队列；最后一名存活玩家离开才结束全场；重连不自动恢复参战身份。
- 本轮仍不含：PvP、跨维度同场战斗、外部观众、断线后自动恢复参战身份（多场并行已在工作区实现，未完整验收）。

**状态：未完成、未验收。** 多场并行有真实双端运行（`index=2`、两场独立 session、跨场互不改写与单侧离场通过）；当前构建 `turn-action-2026-10-27T075951` 已通过真实 `opt-end → 朝向` 推进与同 epoch 跨场拒绝，`recovery2-1793088331733` 已通过附近直接加入。早先 `isolation-...074817` 的 FAIL/UNRESOLVED 分别源于夹具未点朝向与探针未发包，已不作当前结论。进行中的代码与自测不构成本节已达成。

**授权分层（长期约束）**：阵营关系与“是否轮到本人”是两个独立授权层。关系策略只回答“这两个单位是友、是敌、还是无关”；成员资格、当前 action actor、会话/回合戳才决定“谁可以动作”。未来实现 PvP 时，任何关系层都不得放宽动作授权，反之亦然。

## NEXT｜下一阶段：多场并存的剩余工作（已在工作区实现，验收未闭合）

目标：不同地点的多个小队可各自同时开战，互不串扰。

> 历史记录：本节最初写作「未开始」，当时 `primary()` 还是全局单 owner。现在多场注册表、按实体键控的效果容器、战区隔离与定向网络都已落地并有部分真实运行证据（`server index=2`、两场独立 session、跨场拒绝、附近直接加入）。以下保留原始改动清单，括号内为当前进展，不抹掉历史表述。

- 会话注册表：由单场 `primary()` 扩展为真正的多场注册表，会话创建、销毁、玩家归属迁移都要幂等。（**已实现**：`SessionIndex` 按 sessionId 注册；`primary()` 退化为「唯一一场」便捷读取）
- 效果与冻结按会话键控：现有全局效果 / 冻结 / 计时存储需要改为按 sessionId 或战区归属隔离。（**已实现为按实体键**：`BattleEffects` 以实体 UUID 索引，`forget(entity)` 由各自的 `ServerBattle` 调用；`clear()` 仅测试使用）
- 事件路由与战区隔离：伤害、爆炸、友方 NPC、增援、燃烧等事件必须只作用于本场；重叠战区的归属规则要明确。（**部分**：跨场互不改写在状态层已有证据；A/B 双向实际移动/攻击的费用、日志、状态隔离仍缺一次完整闭环）
- 网络定向：每个接收者只收到本场数据，并显式携带 sessionId；客户端遇到未知或非本场 sessionId 必须丢弃而不是猜测。
- 生命周期：多场并发下的行动者离开、敌人目标解析、日志与预警分流、清理幂等。

验收（缺一不可）：两场同时进行、互不串扰——两场各自的效果/冻结/日志/预警/生命周期不越界；每场独立管理者与 ATB；任一场结束不影响另一场；服务器 tick 预算与包量有实测记录。**现状：工作区候选已实现并有真实双端运行（`server index=2`、两场独立 session、跨场互不改写与单侧离场通过）；当前构建的 `turn-action-2026-10-27T075951` 证明真实 `opt-end → 朝向点击` 后 A 的 `epoch 1→2 / ap 100→150`、B 权威不变，且同 epoch 跨场 `EndTurnPacket` 被拒。承载与包量仍未测量，多场重叠拒绝路径未跑通——不得以接口存在或单次运行代替完整验收。**

## LATER｜长期：玩家阵营、关系策略与 PvP（未排期，玩法另定）

- **玩家阵营持久化**：阵营归属于玩家（而非会话），需持久化存储、与存档/维度解耦、缺省值与会话内临时覆盖规则。
- **关系策略**：盟友 / 敌对 / 中立的矩阵，含 NPC 与队伍的关系推导；同一策略供选目标、技能合法性、友伤判定共用。
- **PvP 同意与友伤规则**：挑战/同意流程、决斗边界、友伤开关、安全区、逃跑与投降、死亡惩罚归属。
- **权限与防滥用**：谁可邀请/移出/开战/修改关系；防止借邀请拖人入战、借关系修改绕过回合授权；审计日志与速率限制。
- **玩法与数值**：奖励、平衡、阵营选择界面与引导，需要单独设计确认。

上述任一项都**不是**“接口已就绪即可开工”的同义词：多场隔离（NEXT）与阵营关系（LATER）都会改变当前冻结的契约，需要重新确认范围。

# Tactical — 回合制战术战斗 mod 设计文档

> mod id：`tactical`（显示名待定）
> 目标版本：1.21.1 NeoForge（主线）→ 1.20.1 Forge → 26.1.2 NeoForge
> UI：ApricityUI（AUI）1.2.8，三个版本均有 Maven 发布
> 状态：v0.1 历史设计草稿，不是当前版本规则。当前 AP 积攒、恢复、连续操作费用和站位伤害以 [README](../README.md)、[更新记录](../CHANGELOG.md) 与 [扩展说明](extending-battles.md) 为准。

---

## 1. 一句话定位

把 Minecraft 从实时动作战斗改造成**基于方块的回合制战术 RPG**：玩家带上仇恨就进入格子战斗，世界其余部分照常运转；没仇恨时一切照旧。

## 2. 已确认的设计决策

| # | 议题 | 决定 |
|---|------|------|
| 1 | 网格 | 1 格 = 1 方块，四方向移动，可跨 1 格高差（±1），2 格落差不可翻越 |
| 2 | 行动资源 | AP 制：移动 / 攻击 / 道具 / 方块操作 / 逃跑各有消耗，剩余 AP 不累积 |
| 3 | 回合顺序 | 个体先攻：按先攻值排序，玩家与每个实体各自独立回合 |
| 4 | 战斗区域 | 以玩家为中心圆柱：半径 24，垂直 ±16 |

| 6 | 攻击数值 | 沿用原版武器伤害/附魔/护甲；近战按相邻格判定，弓弩按射程 + 视线 |
| 7 | 敌人 AI | 基础战术：近战逼近、远程拉开距离、绕开障碍 |

| 19 | 参战上限 | 16 个实体；超出/屏障外的敌对实体清除仇恨，不排队、不增援 |
| 20 | 存档 | 战斗中退出重进直接结束战斗，回到普通模式 |
| 21 | 特殊实体 | 首版禁用/退化：飞行、爬墙、自爆、传送 |

| 24 | 逃跑时效 | 10 秒内不重新仇恨 |
| 25 | 实体占位 | 统一 1×1 格 |
| 26 | 友方单位 | 宠物/召唤物/铁傀儡作为友方参战，共享玩家阵营回合 |

## 3. 战斗状态机

```
PEACE ──触发──▶ DEPLOY ──▶ TURN_LOOP ──▶ END ──▶ COOLDOWN ──▶ PEACE
  ▲                            │
  └──────── 玩家死亡/退出 ──────┘
```

- **PEACE**：完全原版。每 10 tick 扫描一次触发条件。
- **DEPLOY**：建立战场快照（区域、参与者、格子对齐），冻结区域实体，弹出 HUD。
- **TURN_LOOP**：按先攻队列轮流行动；玩家回合等输入，敌方回合由 AI 驱动。
- **END**：解冻、清理屏障、恢复自由移动；给 3 秒冷却防立刻重触发（逃跑另有 10 秒仇恨抑制）。
- 退出存档 / 切维度 / 死亡 → 强制 END。

## 4. 战斗触发与战场

### 4.1 触发条件（服务端）
1. 区域内存在 `Mob` 且 `getTarget() == 玩家`；
2. 玩家攻击了某个 `LivingEntity`（`AttackEntityEvent`）；
3. 玩家受到伤害，且伤害来源是敌对实体或“对玩家有仇恨”的实体。

敌对判定：`MobCategory.MONSTER`、实现 `Enemy`、或带 `tactical:hostile` 实体标签（数据包可扩）。

### 4.2 战场
- 圆柱：水平半径 24，垂直 ±16，中心 = 触发时玩家所在方块坐标（固定，不跟随玩家）。
- 区域内所有非玩家 `LivingEntity` 冻结（`setNoAi(true)` + 速度清零 + 位置对齐格心）。
- 玩家同样被“放置”到格心，进入格子移动模式。
- 敌对实体按距离取最近 16 个参战；多出来的清除仇恨并推出屏障外。
- 区域外进入的实体：被屏障挡回并清除仇恨，不冻结、不参战。

### 4.3 屏障与仇恨清除
- 参战上限 16：只接管最近的 16 个敌对实体，多出来的清 `setTarget(null)` 并推到屏障外。
- 客户端渲染半透明屏障（粒子 + 边界框）；服务端阻止外部敌对实体进入，越界即推回并清除仇恨。
- 屏障外不排队、不增援：本次战斗只打已接管的这一批。
- 场上参战敌人全灭或全部失去仇恨 → 战斗结束，屏障立即消失。

### 4.3.1 战场伤害隔离与动态扩展（0.3.0 加入）
- 战场内外的单位**不能互相造成伤害**：参与者不能打外部（防拉扯），外部也不能打参与者（防远程白嫖）。
- 外部敌对生物攻击参与者时，不是简单地被挡住，而是被**吸收进战斗**：战场半径扩展到覆盖它，冻结并加入回合队列。
- 外部玩家攻击参与者：目前拦截并提示（多人联合作战尚未支持）。
- 战场半径随吸收动态扩大，客户端边界环同步更新（`BattleStatePacket.zoneRadius`）。
- 战场交互：HUD 仅展示；按 `B` 打开 `ApricityScreen` 指令菜单（有鼠标），可结束回合/逃跑。

### 4.4 玩家逃离
- 按钮“逃跑”消耗 50 AP，进行一次判定（基础成功率 50% + 移速修正 + 周围敌人数量惩罚）。
- 成功：战斗 END，玩家获得 10 秒 `flee_immunity`（敌对实体不锁定），期间玩家主动攻击立刻重新触发。
- 失败：本回合 AP 清零，敌人正常行动。

## 5. 网格与移动

- 坐标：`GridPos(x, y, z)`，整数方块坐标；实体占据 `(x, y, z)`，脚在 `y`，身高占 `y`、`y+1`。
- 可站立：`blockBelow(x,y-1,z)` 有碰撞、`(x,y,z)` 与 `(x,y+1,z)` 无碰撞（半砖/楼梯按实际碰撞盒）。
- 四方向移动；目标格高度取 `y-1 / y / y+1` 中可站立的最高值，只允许 ±1。
- 不可通行：水/岩浆（首版）、关闭的门、梯子/藤蔓（首版）、其他实体占据的格子。
- 移动执行：逐格动画（150 ms/格），客户端插值，服务端在每一步到达后扣除 AP 并校验；被打断则停下。
- 寻路：A*，四方向，代价 1，高度变化代价 1；启发式曼哈顿距离；限制在战场圆柱内。

## 6. 回合与先攻

- **ATB 行动条（0.4.0 起）**：每个参与者按先攻值充能，谁先充满谁行动，行动后清空。
  - 先攻值 = `attackSpeed × 10 + moveSpeed × 20 + rand(0..9)`
  - 行动频率与先攻成正比：快的单位在一场战斗中行动次数更多
  - 顶部 HUD 用文本条（`████░░░░` + 百分比）实时显示每个人的充能进度
- 先攻最高的单位通常先手；后续顺序由充能速度决定。
- 每回合开始：AP 回满，状态持续时间 −1 回合（二期）。
- 回合结束条件：玩家点“结束回合”/按 `R`/AP 不足（可配置自动结束）。
- 中途吸收的新敌人以 0 进度加入行动条。

## 7. AP 系统

### 7.1 基础公式（可在配置中调）
| 项目 | 公式 / 值 | 默认玩家 |
|------|-----------|----------|
| AP 上限 | `clamp(round(100 × (0.5 + 5 × moveSpeed)), 50, 150)` | 100 |
| 移动 1 格 | `clamp(round(1.2 / moveSpeed), 4, 24)` | 12 |
| 近战攻击 | `clamp(round(48 / attackSpeed), 10, 80)` | 30 |
| 弓 | 35（固定） | 35 |
| 弩 | 50（固定） | 50 |
| 使用道具 | 20（固定，可被修饰） | 20 |
| 逃跑 | 50 | 50 |
| 挖掘方块 | `clamp(20 + 硬度 × 4, 20, 40)` | 20–40 |
| 放置方块 | 15 | 15 |
| 容器/按钮/门 | 10 | 10 |

- 上限与移动消耗都随移速走：快 = 动作多、走得便宜，这是“敏捷型”定位；后续可用装备/药水修饰。
- 攻速快的武器单次攻击更省 AP（匕首≈24，剑 30，斧 48，锤 80）。
- 修饰接口：`ApModifier`（加法/乘法），供饰品、药水、职业被动使用；首版只保留接口 + 配置项，不接内容。

### 7.2 AP 不足
- 点击目标格时若 AP 不够，按钮变暗并显示原因；
- 回合内 AP 用尽自动结束回合（可在配置关闭）。

## 8. 攻击与伤害

### 8.1 近战
- 目标格与自身格满足：`|dx| + |dz| = 1`（四邻）且 `|dy| ≤ 1`。
- 执行：临时把所选武器放到主手 → 调用原版 `player.attack(target)` 走完整伤害/附魔/击退管线 → 还原主手。
- 击退在战斗中衰减为 0（位置由格子决定，避免脱离网格），伤害数字保留。

### 8.2 弓 / 弩
- 射程：弓 16 格，弩 24 格；高打低每 2 格高差 +2 射程（上限 +4）。
- 视线：从眼睛到目标中心做方块射线检测（`ClipContext`），高差 ≤1 时跳过检测。
- 命中即结算：生成视觉箭矢（不参与伤害），伤害按 原版弓基础 6 + 力量附魔 + 速度系数 计算，走 `damageSources().arrow(...)`。
- 箭/弩箭按原版消耗；弩无需装填动作（首版简化）。

### 8.3 伤害修正
- 高度：每格高差 ±5%（上限 ±15%）。
- 护甲/附魔/药水：完全交给原版 `hurt` 管线。
- 暴击：首版关闭（没有跳跃下落）。
- 友方误伤：默认关闭（`CombatRules.friendlyFire = false`）。

---

## 9. 高度与视线

- 移动：仅 ±1 格高差；2 格以上不可跨越（除非以后加攀爬/跳跃技能）。
- 近战：`|dy| ≤ 1`，相邻格。
- 远程：任意高度，但需要视线；2 格以上高差必须过 LOS 检测。
- 高地：每 1 格高差 +5% 伤害（攻高打低），反向 −5%；远程额外 +2 射程 / 每 2 格。
- 视线遮挡：所有带碰撞的方块都遮挡；树叶/玻璃按原版判定（首版不搞例外表）。

## 10. 敌方 AI（首版）

每回合执行一个“行动序列”，直到 AP 不足或无事可做：

1. 若相邻且有近战武器 → 攻击；
2. 若有远程武器且目标在射程内 + 有视线 → 射击；
3. 否则用 A* 向最近敌对目标移动，每步扣 AP；
4. 远程单位若目标过近（≤2 格）→ 反向拉开距离；
5. 无法接近/无法攻击 → 结束回合。

- 目标选择：最近玩家阵营单位（玩家优先）。
- 不做仇恨转移、技能、协同（二期）。
- 行动节奏：每步 200 ms，可在配置调成“快速”。

## 11. 玩家操作与 AUI 界面

### 11.1 操作
- 点击格子移动（高亮可达范围/消耗/路径）。
- 点击敌人：显示目标信息（HP/护甲/距离/高差/预计伤害）。
- 行动按钮：攻击 / 道具 / 方块 / 逃跑 / 结束回合。
- 攻击 = 从背包选武器 → 选目标 → 结算（近战需相邻，远程需射程+视线）。
- 道具 = 打开自定义道具栏，选择可用物品（食物/药水/投掷物）。
- 方块 = 子菜单：挖掘 / 放置 / 交互；点击方块执行，扣 AP。
- 战斗中禁用原版 WASD 移动、跳跃、攻击键（客户端拦截 + 服务端位置校验）。

### 11.2 AUI 页面（三个版本共用）
| 页面 | 宿主 | 内容 |
|------|------|------|
| `ui/battle_hud.html` | Overlay（intercept） | 先攻条、当前回合、AP 球、行动按钮、目标信息、提示 |
| `ui/item_picker.html` | Screen | 背包网格、武器/道具筛选、AP 消耗预览 |
| `ui/block_menu.html` | Overlay/Screen | 挖掘/放置/交互模式切换 |
| `ui/theme` | — | Ore 主题（`/apricityui/theme/ore/ore.css`），只写业务样式 |

- 数据绑定：服务端 → `BattleSnapshot` → 客户端 `UiBridge` → AUI Document 更新（Java 侧操作 DOM / 注册事件）。
- 网格高亮和屏障不用 AUI：走世界渲染（方块边框/半透明面）。
- 页面文件放 mod 资源，开发期同时映射到 `<game>/apricity/` 便于 AUI 热重载。

## 12. 逃跑、结束与奖励

- 逃跑：见 4.4。
- 结束：解冻所有实体、清空 AP/回合状态、移除屏障、恢复玩家控制。
- 奖励：掉落/经验全部走原版；不做战斗结算奖励面板（二期）。
- 玩家死亡：END + 原版重生流程。

## 13. 相机

- 默认不动相机。
- 软兼容：检测 `dungeons-perspective`（NeoForge/Forge）→ 可选切到其越肩视角；未安装则无感。

## 14. 网络与存档

- 服务端权威，所有规则判定在服务端；客户端只发意图、收快照。
- 意图（C2S）：`MoveIntent(cell)`、`MeleeIntent(targetId, slot)`、`RangedIntent(targetId, slot)`、`UseItemIntent(slot)`、`BlockActionIntent(pos, type)`、`FleeIntent`、`EndTurnIntent`。
- 快照（S2C）：`BattleSnapshot`（阶段、回合队列、当前行动者、AP、参与者位置/血量、可达格、屏障状态、提示文案）。
- 首版单人/局域网：每玩家一个 session；实体归属唯一 session；第二玩家进入同区域暂不联合作战（二期）。
- 存档：不持久化战斗状态；退出即结束。

## 15. 工程架构

### 15.1 模块
```
SRPG_MOD/
├── common/                 # 纯 Java 17，零 Minecraft 依赖
│   └── src/main/java/...   # 网格、A*、回合引擎、AP、战斗状态机、AI 规划、DTO
├── neoforge-1.21.1/        # 主线 mod，NeoForge 21.1.x + ModDevGradle
│   └── src/main/java/...   # MC 适配器、事件、网络、AUI UI、渲染
├── forge-1.20.1/           # 后续
├── neoforge-26.1.2/        # 后续
├── ui/                     # 三版本共用的 AUI 页面/CSS
└── docs/
```

### 15.2 common 的抽象边界
`common` 不 import 任何 `net.minecraft.*`，只定义接口与纯逻辑：

| 接口 | 职责 | 版本侧实现 |
|------|------|-----------|
| `GridWorld` | `canStand/canPass/heightAt/hasLineOfSight` | 读 Level + 方块碰撞 |
| `Combatant` | 实体句柄、位置、属性快照、血量、队伍 | 包装 `LivingEntity` |
| `CombatPort` | 造成伤害、使用物品、消耗箭、播放动画/音效 | 调用原版管线 |
| `ZonePort` | 冻结/解冻实体、屏障渲染通知、传送对齐 | `setNoAi` + 客户端包 |
| `TurnScheduler` | 纯逻辑回合队列 | 无 |
| `Pathfinder` | 纯 A* | 无 |
| `ApCalculator` | 纯公式 | 无 |
| `EnemyPlanner` | 纯决策（基于 `GridWorld` 查询） | 无 |
| `BattleSession` | 状态机、动作校验、参战名单 | 无 |
| `UiBridge` | 推送快照、弹道具栏、读输入 | AUI 实现（版本侧） |

这样 common 覆盖约 70% 的规则代码；三个版本各自只写适配器与注册。**代价**：所有跨边界数据要用 DTO（`GridPos`、`CombatantSnapshot`），不能直接传 `Entity`。

### 15.3 版本差异处理
- 1.21.1 NeoForge 与 1.20.1 Forge 的差异集中在：`ResourceLocation`、`DataComponents` vs NBT、属性修饰符、事件总线、网络 API、Screen 注册。
- 这些全部收敛在版本模块，common 不受影响。
- 26.1.2 若 API 再次大改，同样只改适配器；AUI 26.1 分支已存在。
- 若后期某版本适配成本过高，可改用 Stonecutter 预处理公共源码，届时再评估。

### 15.4 依赖
- AUI：`com.sighs:ApricityUI-neoforge-1.21.1:1.2.8`（Maven `https://maven.sighs.cc/repository/maven-releases/`）；1.20.1 用 `ApricityUI-forge-1.20.1:1.2.8`。
- AUI 作为必需依赖写进 `neoforge.mods.toml` / `mods.toml`。
- 相机兼容 mod 用 `ModList.get().isLoaded` 软检测，不写死依赖。

## 17. 风险与待定

1. **AUI Java 侧数据绑定 API**：需要先做 M1 技术验证（读 `Document`/`Element`/`Event` 源码），确认能动态改 DOM、注册点击回调；不足时退化方案是页面通过 KubeJS 或本地 HTTP 拉快照。
2. **冻结实体**：`setNoAi` 可能停不干净（物理、碰撞、寻路），必要时对 `Mob#tick` 加 mixin（版本侧）。
3. **点击移动 + 原版输入**：要处理攻击键误触、视角点击穿透、容器打开等；M1 先做输入锁。
4. **多人**：首版不做联合作战，但包结构预留 session 归属。
5. **数值平衡**：AP 公式是首版拍脑袋值，M2 后按手感调；全部走配置。
6. **性能**：区域扫描 10 tick 一次、A* 半径 24、参战 ≤16，理论上没问题；大规模刷怪场需实测。

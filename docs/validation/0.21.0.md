# 0.21.0 Validation Record

> Note: paths such as `evidence/...` refer to the evidence directory of the private development
> tree and are **not** part of this public source snapshot. They are kept only to record where the
> observations were made; no such files exist here and cannot be checked from this snapshot.

Environment: Minecraft 1.21.1 / NeoForge 21.1.216, ApricityUI 1.2.8, Dungeons Perspective 3.6.3, JDK 21, `main` branch. This release is NeoForge-only.

Verified in this integration round:

- `:common:test :neoforge-1.21.1:build` completes after the skill client sources are present.
- `serverSkillsTest` passed with **546 assertions**, including persistent MP, native rear skill damage, AP/MP reservation and refunds, cooldown, equipment grants/enchantments, target/LOS/formula preflight, composite areas, effects, extension APIs, and ordinary native bow behavior.
- `serverTeamsTest` passed: explicit friendly admission, safe deployment, independent AP/queue, opponent isolation, friendly cap 16, hostile-only caps/refill/victory, friendly-fire/target protection, NoAi restoration and cleanup.
- `serverAiSkillsTest` passed: registered boss adapter, real skill definitions/NBT source, read-only availability, rejected invalid intents, one authoritative AP/MP/effect commit, replay guard and cooldown isolation.
- The initial team failure was a fixture issue caused by `ServerPlayer` spawn invulnerability; the fixture now clears that native guard before the friendly-fire assertion. Production code was unchanged for that fix.

The integrated unit/build suite passed after the client sources and fixes were present. The final package contains YiRanExpressionLib 1.0.1 at `META-INF/jarjar/YiRanExpressionLib-1.0.1.jar`, metadata range `[1.0.1]`, and no root-level `net/yiran` library classes.

A real client was launched with the current build. The battle menu's real mouse click opened the skill menu and displayed `MP 100 / 100 · 自己回合恢复 +0`; an ungranted character displayed “当前角色与装备未提供技能”. This confirms the menu entry, page, MP state and empty-skill state. The live client also confirmed the real skill button click and skill page rendering. The follow-up real-client acceptance on 2026-10-24 completed the remaining cases using Agent Helper's native Minecraft mouse/key callbacks, with Dungeons Perspective loaded:

- An equipped `custom_data` source displayed backstab Lv.3. Clicking the skill and the rear target changed target HP **200 → 189.5**, AP **100 → 85**, and MP **100 → 90**. Reopening the skill menu showed cooldown **1 turn**, its unavailable reason, and the next shared-ramp cost **19 AP**.
- Clicking Attack with a wooden sword displayed the small orange melee range and a green validated target frame. Switching to a bow displayed the larger orange range and validated target frames. The melee capture waited for the asynchronous range response rather than treating the initial updating state as evidence.
- In MOVE mode, a dandelion at `(1,99,-1)` and short grass at `(2,99,-1)` both exposed the underlying reachable cell. Real mouse clicks moved the player to `(1.5,99,-0.5)` and `(2.5,99,-0.5)` respectively, with AP **100 → 88 → 76**. Hover and arrival screenshots were inspected.

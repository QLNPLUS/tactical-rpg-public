# Tactical RPG

把 Minecraft 战斗改造成**基于方块的回合制战术 RPG**的模组。

- 当前开发与验证目标：`main`，**Minecraft 1.21.1 / NeoForge 21.1.216**
- 前置：ApricityUI（AUI）**1.2.8**
- 1.20.1 Forge、26.1.2 NeoForge 尚未移植或测试

设计文档：[设计说明](docs/DESIGN.md)；开发接口：[扩展战斗](docs/extending-battles.md)。

### 技能与 MP

- 技能可由玩家持久数据、主副手/护甲 `custom_data` 和附魔授予，多个来源取最高等级；换装备会刷新技能，冷却保留。
- MP 默认上限 100；入战保留实际余额，战斗内默认恢复 0，战斗外默认每 200 ticks 恢复 20。最大 MP 与恢复量均是原生属性。
- 技能可指定敌人、友军或自身，支持地面/实体/自身瞄准、范围组合、公式伤害、效果、等级和冷却。技能 AP 费用加入已有连续操作涨费，MP 不加入计数。
- `tactical:backstab` 是首个背刺示例：主手近战、背后目标、最高 5 级，技能倍率 `1 + 0.25 × level`，AP 15、MP 10、冷却 1。

### 友军与范围预览

- `BattleParticipation.tryAddFriendly` 和 `BattleSide` 提供第三方友军参战与阵营查询，友军上限独立为 16。
- 攻击瞄准时橙色格子表示几何射程，绿色实体框表示服务端距离/碰撞/弹道检查通过的目标；最终攻击仍重新检查 AP、弹药和视线。
- 移动模式使用碰撞体射线，草、花等无碰撞装饰不会挡住可站立格子的高亮和点击。

## 0.20.0 功能沿革

以下是 0.20.0 引入的功能说明；历史发布说明 `dist/release-notes-0.20.0.md` 属于私有开发树的发布产物，**不在本源码快照中**，历史验收范围见 [0.20.0 验证记录](docs/validation/0.20.0.md)。当前版本与协议以上文及下方安装说明为准；功能说明不代表新增运行时验收。

### 朝向与高度伤害

- **战斗内近战与箭矢**：仅同场参战者之间的玩家 / 生物直接近战，以及真实箭矢（不含投掷三叉戟）获得位置修正。相对目标的**身体朝向**，正面夹角不超过 45°（含边界）为 ×1，侧面为 ×1.2，背面夹角至少 135°（含边界）为 ×1.5。
- **高低差**：分别向下取整双方脚底 Y，再计算 `floor(来源脚底Y) - floor(目标脚底Y)`；每高一格 +5%，每低一格 −5%，倍率限制为 ×0.85–×1.15。箭矢按命中时的水平来向和发射时射手的脚底高度结算，射手之后移动不改变这一高度；缺失或失效的发射高度记录采用中性 ×1。
- **独立结算**：位置倍率在原版护甲等减伤之后、吸收生命之前生效，朝向、高度、技能与防御分别相乘。防御确认的朝向影响受击扇区，但现有防御仍覆盖所有角度：普通防御 ×0.5，副手盾牌防御 ×0.3，持续至下个自身回合。
- **适用范围**：药箭的物理命中可获得位置倍率，附带魔法 / 药水伤害不获得。魔法、爆炸、火焰、摔落、药水、荆棘与投掷三叉戟不获得位置倍率；原本符合防御条件的伤害继续保留既有防御减伤。默认技能倍率为 ×1；本版提供扩展接口，没有内置“背刺双倍”技能。接口与示例见 [伤害倍率扩展](docs/extending-battles.md#朝向高度与技能伤害倍率0200)。

### AP 储备与连续操作

- **入场 100 / 上限 150 / 后续自身回合恢复 50**：玩家、敌人和后续增援共用规则。初始 AP 不超过自身上限；首次自身回合不额外恢复，之后每次自身回合按 `min(上限, 当前AP + 恢复量)` 恢复，保留余量，不重置为满值。
- **固定上限基准**：AP 上限不再由移动速度决定。原生 `tactical:max_ap` 仍是百分比，默认与已有存档值 `100` 均表示固定基准 150 的 100%；提高上限不补 AP，降低上限会截断当前 AP。新增原生同步属性 `tactical:ap_recovery`，默认 50，表示绝对恢复量，可用 `/attribute` 在运行时修改。
- **基础费用**：近战 10、弓 15、弩 20、普通道具 8、方块放置 10 AP。每个行动者的成功攻击 / 道具使用 / 放置共享本回合计数，第 `countBefore + 1` 次操作费用为 `ceil(基础费用 × (1 + 0.25 × countBefore))`。失败不增加计数，自身回合开始清零；移动不加入计数，防御仍固定 25、逃跑仍固定 50 AP。
- **费用示例**：同一回合先近战消耗 10 AP，再用道具消耗 10 AP，再射弓消耗 23 AP。下一自身回合重新从各自基础费用开始。旧攻击速度 AP 费用公式不再适用；原版武器的冷却、蓄力、弹药、附魔与耐久等机制保留。

### 原生头顶血条

头顶血条改为紧凑边框：敌人暖红、玩家青绿，当前行动者或悬停定位目标显示金色边框。血条跟随模型的逐帧渲染位置与渲染偏移，减少移动时的跳动及边框闪烁；具体视觉验收状态见本版验证记录。

### 持续仇恨入场与名册

- 活动战斗每 10 个服务端 ticks 查询战场包围盒向各方向扩展 8 格内的存活敌对 Mob，仅接纳当前 `target` 正是战斗拥有者的单位；按距拥有者由近到远尝试安全吸收，直到敌人数达到上限。无仇恨、中立、目标是别人或已放弃追击拥有者的单位不加入；远处盒外单位不扫描，但直接场外攻击仍走吸收入口。
- `participantCap` 只计敌人、不计玩家，也约束场外攻击者吸收。初始普通 / 强制开战候选必须在初始区域内，安全部署成功才占名额。死亡 / 移除腾出名额后，在胜利判定前立即补充合格追击者，延续同一场战斗及已有单位 AP / 回合队列；新增援军单独按入场 AP 初始化。
- 未参战单位保留普通 AI 与仇恨，不清仇恨或冻结；入场保留地面 / 飞行安全部署检查。
- 顶部肖像与左侧名称均可定位同一单位，互相高亮，并联动世界轮廓及镜头；定位状态按悬停来源管理，移开或单位死亡后清理，不消耗 AP、不切换操作模式。

### 界面、移动与战斗规则

- **固定左侧布局**：生命名册固定左上，显示实际 HP / 最大 HP；纪事固定左下，避让名册、聊天、生命与快捷栏安全区。空间不足时减少行数、仅留标题或隐藏，不移到中间列。
- **共享蓄力肖像轨道**：顶部一条不填充的共享轨道同时显示全部参战者真实实体肖像，不分页、不轮播，也没有每人独立进度条。肖像横向位置按蓄力比例计算，当前行动者在终点；重叠只沿竖直方向错层。
- **九档界面尺寸**：按钮切换 60 / 70 / 80 / 90 / 100 / 110 / 125 / 140 / 160%，重置为 100%；名册与纪事字体随尺寸调整。
- **快捷栏与原版背包**：所有战斗阶段保留原版快捷栏与状态 HUD，仅隐藏准星。世界 / 战术界面中的 1–9（可重绑）和普通世界滚轮切换主手槽，不退出移动、瞄准或朝向模式；E 打开原版 `InventoryScreen`，聊天和容器保留自身输入。
- **主手道具**：通过“道具”使用当前主手，方块进入放置模式；仅在玩家回合、非移动 / 投射物等待期间执行。服务端检查当前槽与原版动作结果，只对成功接受的动作扣除当前报价并增加连续操作计数；弓弩走攻击，盾牌走防御。
- **镜头与界面输入分流**：在世界区域按住中键才允许地牢视角平移及中键 + 滚轮缩放；悬停可见 GUI / HUD 时优先界面操作。从界面起始的中键手势不能拖入世界后变成镜头操作。
- **战斗纪事**：显示回合、移动、攻击、伤害与状态事件；支持点击收起 / 展开和滚轮浏览历史。最新位置跟随新消息，浏览历史时按条目锚定；聊天或物品栏打开时隐藏，战斗结束消失。
- **窗口入场**：初始布局提交且面板边界连续两帧稳定后执行 200 ms 透明度淡入，不缩放或平移；首次资源载入仍可能短暂卡顿。
- **绕路 / 直接跳下**：普通移动按可站立路线逐格行走；相邻低处可直接跳下。两条路线都可行且 AP 足够时显示费用与落差供选择；只有一条时直接执行。检查玩家碰撞体，不穿墙、不瞬移；直接跳下消耗一步 AP，超过 3 格仍结算摔落伤害。
- **安全部署**：地面单位搜索附近最近安全站立位置，检查全身碰撞、旁观实体、支撑与危险方块，保留合适的非整数 X/Z；支持的飞行类型采用空中安全检查。无候选就跳过。范围见 [扩展战斗](docs/extending-battles.md)。
- **幻翼空中战术**：保留安全的实际悬空位置（含分数高度），仅自身回合按三维碰撞路线接近。完整俯冲支付当前近战报价（默认首次 10 AP）与往返全部移动费用后返回原位；预算不足仅付费接近，不免费回返或攻击。非自身回合关闭普通 AI 并保持悬停。
- **弓弩转向与弹道检查**：任意初始朝向均可选敌射击，服务端先检查真实方块 / 生物碰撞；无法到达目标时拒绝，不扣 AP、弹药或耐久。继续使用真实原版箭矢，中央弹道确定化，多重射击侧箭保留原版行为。
- **骷髅远程战术**：仅普通骷髅持弓时使用远程行为，为当前弓报价（默认首次 15 AP）预留预算，绕掩体、接近或后退以争取 4–16 格射击位置；每个自身回合最多一箭，等待飞行结算后推进。流浪者与沼骸尚未接入。
- **效果与食物按自身周期推进**：首次自身回合及新增 / 实质刷新的效果先建基线，之后每完整自身周期扣除 200 ticks 的有限效果时间，周期伤害 / 治疗最多执行一次。食物消耗、疲劳、自然回血和饥饿按自身周期处理；着火每周期最多一次原版 1 点伤害，保留抗火、火焰免疫及水雨灭火，熔岩接触伤害不改。详见 [效果时间规则](docs/effects-turn-time.md)。
- **苦力怕与预警**：水平距离 1–2 格、垂直差不超过 1 格且有视线时准备爆炸，到下个自身回合引爆。露出的碰撞顶面显示保守红色预警，考虑充能与爆炸半径；不计算墙体遮挡，也不保证方块会被破坏，实际走原版爆炸规则。
- **成功逃跑保护**：保留 50 AP 与原概率；成功后清除对玩家的仇恨，在 200 个真实服务端 ticks（正常 10 秒）内阻止重新锁定，不是无敌。归因于玩家的生命伤害或消耗吸收生命的伤害会提前取消保护；挥空、零伤害、取消及完全格挡不取消。之后自动开战仍遵守开关。
- **死亡与会话清理**：保留玩家死亡 / 重生清理与玩家身份隔离。当前仍是单玩家战斗会话，不支持多人共同参战。

### 基础玩法

- 启用自动触发且无逃跑保护时，敌人仇恨你会**自动进入回合制战斗**；也可 `/tactical battle force` 手动开战。
- **ATB 行动条**：每个单位按先攻速度充能，顶部共享轨道用肖像位置显示进度，满格者行动。
- **玩家回合自动弹出右侧指令菜单**（真实界面、有鼠标）：
  1. 移动 —— 关闭菜单后点击浅蓝色格子，按可行路线行走或跳下；两种路线均可用时先选择。
  2. 攻击 —— 点击敌人，近战需相邻，弓弩按射程；当前 AP 报价随本回合成功操作次数增加。
  3. 防御 —— 固定 25 AP，选择四方向之一并确认后结束回合；全角度减伤 50%（副手盾牌 70%），持续到下个自身回合，取消不扣费。
  4. 道具 —— 当前主手使用或方块放置，基础费用 8 / 10 AP，按连续操作次数报价，仅成功扣费。
  5. 结束回合；菜单也提供逃跑入口（固定 50 AP，仍需概率判定）。
- 其他实体行动时镜头切换到该实体；玩家回合切回玩家。
- 战斗中禁止直接使用物品、吃东西、右键方块、左键破坏；通过菜单执行对应动作。
- 战场内外的单位不能互相造成伤害；场外敌对生物攻击场内目标会尝试安全吸收，战场随入场扩展。
- 战斗中 WASD / 跳跃被冻结，只能通过菜单 + 点击行动；不绘制蓝色边界，保留浅蓝可移动格。
- 配置文件为 `config/tactical-common.toml`。

> 移动是“点击目标格 → 服务端检查路线 / AP → 必要时选择绕路或跳下 → 沿碰撞检查过的轨迹移动”。

## 命令

| 命令 | 作用 |
|------|------|
| `/tactical battle start` | 对附近有仇恨的敌对生物开战 |
| `/tactical battle force` | 强制接管附近所有敌对生物（测试用） |
| `/tactical battle stop` | 强制结束战斗 |
| `/tactical turn end` | 结束玩家回合（菜单也有按钮） |
| `/tactical flee` | 尝试逃跑（菜单亦有按钮，50 AP；失败耗尽剩余 AP 并结束回合） |
| `/tactical ap get <targetPlayer>` | 管理员查询战斗拥有者当前 AP（权限等级 2） |
| `/tactical ap add <targetPlayer> <amount>` | 增加当前 AP，最多到当前上限（权限等级 2，amount 为 1–10000） |
| `/tactical ap remove <targetPlayer> <amount>` | 减少当前 AP，最低为 0（权限等级 2，amount 为 1–10000） |
| `/tactical auto on\|off` | 开关自动触发 |
| `/tactical status` | 查看战斗状态 |
| `/tacticalui` | 打开 AUI 测试页（客户端） |

AP 命令只接受一个在线玩家，且目标必须是当前活动战斗的拥有者；不能借此修改敌人或其他玩家的 AP。例如管理员可用：

```mcfunction
/tactical ap get @p
/tactical ap add @p 20
/tactical ap remove @p 10
```

### 战术属性（原版 `/attribute`）

```mcfunction
/attribute @s tactical:max_ap base set 100
/attribute @s tactical:ap_recovery base set 75
/attribute @s tactical:turn_charge_speed base set 1.5
/attribute @s tactical:max_ap modifier add example:ap_bonus 25 add_value
/attribute @s tactical:turn_charge_speed modifier add example:charge_bonus 0.5 add_multiplied_total
```

`max_ap = 100` 对应上限 150，`max_ap = 150` 对应上限 225；按最终百分比计算并四舍五入，最低 1，不依赖移动速度。`ap_recovery = 75` 表示后续每次自身回合恢复 75 AP，首次自身回合不额外恢复。蓄力倍率作用于本场原先攻（含入场时固定的随机值），更改倍率不会重掷先攻或清空蓄力。属性动态生效，上限下降限制当前 AP，上升不会补满。更多说明见 [战术属性与 AP 生命周期](docs/extending-battles.md#战术属性与管理员-ap0200)。

## 网络协议

当前 Tactical 主协议注册版本为 **`8`**（独立技能通道 **`3`**）；客户端与服务端必须同时使用同一版本，旧端会被明确拒绝而不是静默混连。0.23.0 的每条 C2S 意图都携带「会话 UUID + 服务端回合代数」戳，服务端以连接真实玩家身份校验，不信任 payload 自称的行动者。下表列出主要战斗包（非全部）：

| 方向 | 包 | 作用 |
|------|----|------|
| C2S | `MoveIntentPacket` | 请求移动到某格，由服务端计算路线 |
| S2C | `MoveChoiceOfferPacket` | 提供绕路 / 直接跳下的费用与选择令牌 |
| C2S | `MoveChoicePacket` | 选择路线或取消；服务端重新检查 |
| C2S | `AttackIntentPacket` | 攻击某个敌人 |
| C2S | `EndTurnPacket` | 结束回合 |
| C2S | `DefendPacket` | 提交确认的四方向朝向，服务端检查 25 AP 后防御并结束回合 |
| C2S | `FleePacket` | 尝试逃跑 |
| S2C | `BattleStatePacket` | 阶段 / 会话标识与回合代数 / 行动条 / 接收者自身的 AP、上限、恢复量、报价与计数 / 可达格 / 行动者 / 武器 / 血条 / 战场 |
| S2C | `CreeperTelegraphPacket` | 苦力怕准备状态与保守爆炸预警范围 |
| S2C | `BattleLogPacket` | 左下安全区战斗纪事 |

## 自检

`runServerSelfTest` 提供专用服务器回合自检入口；历史单回合自检结果以 [0.20.0 验证记录](docs/validation/0.20.0.md) 为准。

`runServerMultiBattleTest`（系统属性 `tactical.selftest=multi_battle`）是本轮新增的服务端多人自检：管理者单独开战、局外人与等待者的越权拒绝、邀请 / 拒绝 / 重邀 / 接受、占格与安全边界拒绝、旧会话与旧回合戳拒绝、身份敏感关系策略、四成员隔离、公共 API 首次友方招募、以及发起者离开后幸存者继续与最后一人收场。判据是日志出现 `[Tactical] MULTIPLAYER SELFTEST PASSED` **且**进程退出码为 `0`；失败时打印 `MULTIPLAYER SELFTEST FAILED at stage …` 并退出 `1`。构建任务成功**不**等于该自测通过。它使用无头夹具，仍不替代双真实客户端验收。

- E 使用原版背包整理与换装；战斗道具使用 / 放置通过指令菜单并由服务端扣 AP，攻击使用主手武器。

## 自动构建与显式发布

[`.github/workflows/build-release.yml`](.github/workflows/build-release.yml) 是原获批发布工作流（逐字节恢复，未改动）：

- **普通分支 push（含 `main`）、PR**：只做 `validate --java`、离线发布脚本单测、主题检查、`:common:test :neoforge-1.21.1:build`、`check_release.py`、`release_pipeline.py package`，并上传构建产物；**不发布**，发布作业拿不到凭据。
- **`v<版本>-neoforge-1.21.1` 标签 push** 或 **手动 `workflow_dispatch`**：进入 `publish` 作业（`release` 环境、`contents: write`）。默认发布到 **CurseForge + GitHub 两处**，CurseForge 发布类型默认 **`beta`**（可显式选 `alpha` / `release`）；手动运行可显式选 `target=github` 只发 GitHub，摘要会写 `CurseForge NOT enabled`。标签必须与 `gradle.properties` 的 `mod_version` 精确对应，且指向本次构建提交。
- 发布作业**不重新构建**：下载同一次构建的唯一制品包，重跑 `verify --tag` 复核 SHA-256 与元数据后，把同一份 JAR 传 CurseForge、附同样校验和与 `release-manifest.json` 建 GitHub Release；缺 CurseForge 配置时**阻断**而不是假报成功。
